# Spine bow — render-only body-roll legibility (user verdict: no waist joint)

**Problem (user's, from the QA overlay):** the body-roll wave is fully
captured (chest ±0.4 rad, neck ±0.4, phase-offset; pelvis sway + yaw all
in the table) but the rig torso is two straight segments with ONE
internal bend point — the roll rendered as a tilt with a kink, "spine
not bent at all."

**Fix (render-only, `creature.js`):** bow pins. At build, unpinned
body nodes near the pelvis→neck rest line are stored as (t, lateral u).
Per frame they are softly pulled (k = 0.35) onto a quadratic curve
through pelvis / chest / neck: control point derived so the curve
passes through the chest at gain 1, exaggerated beyond it at
`spineBow` > 1 (default 1.8; 0 = off — a workbench knob). Straight
spine → the curve degenerates to the line, so every other move is
untouched by construction. No rig change, no table change, no schema
change; the 21-landmark schema has no mid-spine observation, so a real
waist joint would have been interpolation dressed as a joint — declined
by the user ("too much for this stage").

**Evidence:** `2026-09-28-spine-bow-ab.png` — spineBow 0 vs 1.8 at
roll phases 0.25 / 0.65 (bodyroll-captured forced, manual scrub):
belly hollows and chest arches in the "on" panes where "off" shows a
straight trunk. Bench during capture: 0 spikes, components 1, state
groove. Frame cost: one quadratic eval per bow node (~30 nodes) —
noise vs the 6 ms/frame envelope.

**Also staged:** `web/app/moves/bodyroll-captured.json` (the captured
table, loadable by name for judging — NOT added to the groove
rotation; promotion is a user call after the stage viewing).
