# Mocap retarget lag: measured, root-caused, fixed (brief 16 Task 2)

User observation from the QA videos: the retargeted rig visibly lags the
source dancer.

## (1) Measurement

New diagnostic in extract.mjs: the filtered pipeline's joint-angle
signals cross-correlated against a RAW parallel path (same de-yaw +
retarget, no smoothing), peak refined sub-frame, whole-window + thirds.

| side | filter | lag | thirds | verdict |
|---|---|---|---|---|
| L (2.300–4.767) | One Euro (old default) | **46.6 ms** | 13.7 / 52.7 / 41.7 | DRIFTING |
| R (4.767–6.967) | One Euro | **60.2 ms** | 46.4 / 58.4 / 62.9 | ~constant |
| L | Savitzky–Golay (new default) | **−0.7 ms** | −1.2 / 0.6 / 0.7 | constant |
| R | Savitzky–Golay | **+1.6 ms** | 1.8 / 0.3 / 1.4 | constant |

Root cause: One Euro is CAUSAL — its adaptive low-pass buys smoothness
with phase delay (~1.5–2 frames at 30 fps), and the delay is
velocity-dependent (lag shrinks in fast strokes, grows in holds — hence
the drifting thirds on L). Right for live use, wrong for an offline
pipeline that can see the future. Synthetic contrast in the self-test:
same noisy sine, One Euro 45.6 ms vs SG 0.1 ms, SG residual 0.020 vs
noisy 0.057 (denoises AND zero-phase).

## (2) Fix

`lib/smooth.mjs`: central-point Savitzky–Golay kernel (least-squares
polynomial, symmetric → zero phase by construction), mirror-padded,
applied to landmark positions (never angles — rule unchanged).
`--filter savgol|oneeuro|none` on extract.mjs, default savgol
(window 9, order 3, tunable); One Euro kept behind `--filter oneeuro`
for future live capture only. Filter mode + params recorded in
poses.json provenance. Self-test gains the zero-phase check (asserts SG
< 2 ms AND One Euro shows its known lag — the contrast is the test).

## (3) QA right panel

Confirmed **per-frame retarget**, not table playback: qa-spec frames are
`fkPose(rig, thetaFrames[i])` for every detected frame i (extract.mjs
stage 9). The user's conditional (cycle alignment before averaging if it
were table playback) does not fire. The observed lag was therefore
entirely the filter's phase delay, which also means the DISTILLED TABLES
carried the same smearing — cycle averaging under a drifting 14–63 ms
skew blurs key timing. Both rebuilt.

## Rebuilt outputs

Both sides re-extracted under SG (L: 3/3 cycles kept; R: 2/2 — the
turnaround straddler now falls outside the period fit), QA videos
regenerated, `tstep-captured` + `tstep-captured-x` restitched
(L + aligned real R, seam rotation 0.328, mean travel −0.0001 u/beat).
Stage re-armed over Darude with fresh module state.
