# Brief 17.6 Task 2 — the engine weight layer

`web/app/loaded-modules/creature.js`, "weight layer" block: after FK,
before the (unchanged) stance lock. One dial, `exaggerateWeight`: 0 =
layer skipped (today's engine), 1 = shape defaults, up to 2. **Default 0**
until `docs/explained/weight.md` exists (Task 4's explain-it gate).
Constants on the shape: sidecar `weightLayer` (biped-1/-2/-front/-profile
carry `L` = 0.3054 / 0.2984 / 0.3044 / 0.2952, measured hip→knee→ankle;
the four fractions default in the engine, overridable per shape).

## What it does, in order (per frame, dial > 0)
1. **Weight**, two springs: slow (wn 8, ≈0.25 s) drives what the eye
   reads as the transfer; fast (wn 30, ≈50 ms) picks the support foot for
   grounding. Authored tables without `weight` derive it from contacts.
2. **Pelvis tilt** 4°·weight·dial, support hip up — frontal plane only
   (fades to 0 as the hips overlap: profile hips sit 0.006 apart).
3. **Spine counter**: the upper body turns (1 + counter)·tilt, counter −0.5.
4. **Pelvis shift** 0.06·L·|weight|·dial toward the support foot along the
   view's axis; the support ankle/foot stay, the knee re-solves (drawn
   bone lengths, so depth foreshortening survives; only legs whose
   hip→ankle changed).
5. **Grounding**: the whole body moves vertically so the support foot's
   lowest point (ankle or toe) is on the floor — weighted average in
   shared stance (smoothstep across |w| < 0.3, no pop).
6. A **free foot** pushed below the floor is lifted to it, knee bends.
7. **Sink**: support side flips → +0.03·L·dial down, t²·e attack (no
   velocity step), gone in ≈0.6 beat.
8. **Beat bounce** is put back after grounding, ×0.5 under tables that
   transfer weight, yielding to the sink; unchanged otherwise.
The stance lock then runs as before (lift-yield included). The two-bone
knee solve is now one function used by both the lock and the layer.

## Deviations (stated)
1. **Grounding only on tables with weight content** (any `weight`
   channel, or an authored key on one foot). The brief asks for both
   "shared stance: root to the weighted average" and "weight ≡ 0 renders
   identically" — measured, the two conflict on figures whose FK lifts
   the feet (procedural groove, authored groove: the layer moved them
   0.08 L). Weight-free tables keep today's behaviour exactly; every
   captured table is grounded (the kick's averaged weight never leaves
   ±0.22 but it hung like the rest).
2. **Two springs on weight.** Grounding on the slow one lagged a snap
   transfer ~0.25 s: the kicking foot was held to the floor and the
   planted one hung (tstep-placeholder 0.25 L). Tried and measured
   against "ground the lower foot": that left the weighted foot 0.24 L
   up on the front running man (its depth cue draws the bent support leg
   shorter), so the brief's "support by weight" stays.
3. **Free-foot floor clamp** (not in the brief): grounding by weight
   pushed a lower free foot through the floor (front running man 0.16 L,
   tstep-placeholder 0.22 L) → lifted to the floor, knee bends; now ≤ 0.03.
4. **Vertical grounding only; x stays FK on captured tables.** The A7
   lesson: the running man's support foot slides back along the floor in
   the real move; pinning x would erase it. Authored tables keep the
   lock's x pin as before. "Slide = 0 by construction" therefore holds
   for the HEIGHT of the support foot; Task 3's row measures x slide.
5. Tilt fades in profile (frontal-plane obliquity is invisible there).
6. The stance lock still reads `contacts`; they ARE derived from weight
   (distill emits them from it; authored round-trip exact), so the lock
   was not rewired.
